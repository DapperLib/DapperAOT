# DAP231

When reading a single row, you should probably have a `where` clause. Alternatively, a `top` combined with `order by` would be acceptable.

Bad:

``` sql
select Id, Name
from Users
```

Good:

``` sql
select Id, Name
from Users
where UserName = @cn
```

Also fine:

``` sql
select top 1 Id, Name
from Users
order by CreationDate desc
```

A query whose select list has an aggregate of its own (not one inside a subquery) is not reported,
because without `GROUP BY` it returns one row. That includes an aggregate wrapped in another expression:

``` sql
select COUNT(1), ISNULL(SUM(Balance), 0)
from Users
```

This check does not look at `GROUP BY`, so a grouped query is not reported either, even though
it can return many rows.

A windowed aggregate (`OVER`) returns one row per source row, so it still needs a `where`:

``` sql
select COUNT(1) over ()
from Users
```

So does a schema-qualified function on a column, such as `dbo.Median(Balance)`. It is treated as
a scalar function, even though a CLR aggregate is called the same way. A schema-qualified function
on an aggregate, such as `dbo.FormatMoney(SUM(Balance))`, returns one row and is not reported.
