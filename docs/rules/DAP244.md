# DAP244

A `SELECT` expression without a `GROUP BY` (or with only `GROUP BY ()` or `GROUPING SETS (())`) cannot mix aggregate and non-aggregate results;

Fine:

``` sql
select Name
from SomeTable
```

or

``` sql
select COUNT(1)
from SomeTable
```

An aggregate can be wrapped in other expressions, a windowed aggregate (`OVER`) is evaluated per row,
and with `GROUP BY` the server checks that each non-aggregate column is grouped, so these are also fine:

``` sql
select COUNT(1), ISNULL(SUM(Value), 0)
from SomeTable
```

``` sql
select Name, COUNT(1) over ()
from SomeTable
```

``` sql
select Name, COUNT(1)
from SomeTable
group by Name
```

Invalid:

``` sql
select Name, COUNT(1)
from SomeTable
```

A subquery that refers to a column of the outer query, outside an aggregate of its own, counts as that column, so this is also invalid:

``` sql
select COUNT(1), (select MAX(o.Value) from OtherTable o where o.SomeId = t.Id)
from SomeTable t
```

Only references qualified with a table alias or name (`t.Id`) are detected.

A schema-qualified function such as `dbo.FormatMoney(SUM(Value))` counts as whatever is inside it,
like any other function. A method on a column counts as that column when it is qualified
(`t.Location.STAsText()`); unqualified (`Location.STAsText()`), it looks the same as `dbo.Fn()`,
so it is not detected.

Aggregate functions are [listed here](https://learn.microsoft.com/sql/t-sql/functions/aggregate-functions-transact-sql).
